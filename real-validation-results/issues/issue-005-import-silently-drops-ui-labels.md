# Issue #005 — 导入 JSON 静默丢弃大部分内容却报「导入成功」；单库时删除按钮无解释

Issue ID: ISSUE-005
来源: **用户实报**（非 Pilot 发现）——「导入 json 后根本无法保存信息」「删除功能也无法使用，不管新建库还是基础库」
受影响入口: 资料页 → 导入 JSON →（当前资料库 / 新建一个资料库）→ 校验并导入
Severity: **P1**（数据静默丢失 + 结果谎报成功）
Stage: PROFILE_IMPORT / 字段映射
Status: **fixed**（2026-09-27，含真实扩展界面复验）

## 现象

用户粘贴一份结构完整的中文简历 JSON，界面报「JSON 导入成功，已写入「AI应用 / Agent」」，
但资料编辑器里 **基础信息全空、教育经历 0、实习经历 0、技能空、求职偏好空**，只有项目经历进去了。

真实扩展内实测（映射器 + storage 双侧取证）：

```text
mapResumeJsonToProfile(用户的键结构) → ok = true, errors = []
  basic.name      = ""        ← 整块丢弃
  education       = 0         ← 整块丢弃
  internships     = 0         ← 整块丢弃
  skills.technical= []        ← 整块丢弃
  jobPreferences  = []        ← 整块丢弃
  careerPreferences 不存在    ← 整块从未被映射
  projects        = 1         ← 只有这一块命中
```

## 根因：导入器认的键名 ≠ 应用界面上显示的标签

`importMapper` 的块别名是「个人信息 / 教育背景 / 实习经历 / 技能与资质 / 求职期望」，
而资料编辑器 `<summary>` 上写的是「**基础信息 / 教育经历 / 工作·实习经历 / 技能 / 求职偏好 / 职业方向**」。
用户（以及替他整理简历的 AI）自然照界面上的词写 JSON —— 于是六块里五块被静默丢掉。

条目内层还有四处同类缺口：

| 界面上 / 简历里的写法 | 原来只认 | 后果 |
|---|---|---|
| `主页/作品集` | `个人主页/作品集` | 作品集丢失 |
| `职务`（实习） | `岗位` | 实习职位丢失 |
| `开始` / `结束` | `开始时间` / `结束时间` | 三段经历的日期全空 |
| `技术技能: "A,B,C"`（逗号串） | 不拆分 | 变成 1 个巨型条目，填表时整串写入 |
| `职业方向` 块 | 从未映射 | `careerPreferences` 永远为空 |

第二个根因是**成功判定过宽**：`recognizable` 只要任意一块命中就 `ok = true`，
所以丢了五块照样弹成功横幅 —— 这才是用户感觉「怎么导都没用」的直接原因。

## 修复

1. `BLOCK_KEYS` 常量表：每块的接受别名**必须包含界面上的中文标题**，单一来源。
2. 补齐内层别名：`主页/作品集`、`职务`、`开始`/`结束`。
3. 新增 `asTermList()`：只对**列表语义**字段（技能 / 期望城市 / 期望岗位 / 目标方向）按 `、，,；;|` 拆分。
   **刻意不用于工作职责、项目内容等正文字段** —— 中文正文里满是「，、」，拆了会碎成几十段。
4. 新增 `careerPreferences`（职业方向块）映射。
5. **允许部分导入，但绝不谎报**：`MapResult` 增 `ignoredBlocks` / `unknownTopKeys`，
   `CommitResult` 增 `warnings`，导入面板新增橙色 `banner-warn` 明确列出
   「以下块在 JSON 里有内容，但没能映射进资料：…」。
6. `LibraryPicker`：只剩一个库时删除按钮本就 `disabled`（设计如此），但原来只有一句原生 `title`
   提示 —— 用户完全看不见，以为功能坏了。现在补一行显式说明（`data-delete-hint`）。

敏感字段维持原设计：**恒不从外部 JSON 注入**（`sensitive.*` 一律为空），本次未放宽。

## 回归覆盖

`tests/importMapper.test.ts` 新增 5 例：界面标签六块全落地 / 全映射时不报缺失 /
部分导入必须列出 `ignoredBlocks` 与 `unknownTopKeys` / 敏感字段外部注入被忽略 /
导出信封 round-trip 不丢内容。

真实扩展界面复验（一次性脚本，跑完删除）：

```text
导入后  姓名="占位姓名"  区块=[教育经历（1）, 项目经历（1）]
刷新后  姓名="占位姓名"  区块=[教育经历（1）, 项目经历（1）]   ← 真持久化，非仅内存
storage: portfolio=example.xyz, intern0=[占位公司A, AI应用实习生, 2026.07, 至今],
         skillsTech=[Playwright, REST API, Python], city=[重庆, 成都, 杭州],
         career=[AI应用开发, Agent/Workflow]
单库时  删除按钮 disabled=true 且提示行已渲染（data-delete-hint 命中 1）
```

## 遗留

- 用户那份 JSON 的 `结束: "至今"` 会原样写入离职时间框 —— 站点若期望日期格式仍会判无效，
  这与 issue-003 是同一类格式保真问题，本批未扩大处理。
- 导入器与界面标签仍靠「别名表包含界面用词」来防漂移，没有编译期约束；
  若以后再改界面文案，需要同时改 `BLOCK_KEYS`（已写注释指向这一点）。
