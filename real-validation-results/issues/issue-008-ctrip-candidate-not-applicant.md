# Issue #008 — 携程内推表单里的「候选人X（请勿填写你的个人信息）」

Issue ID: ISSUE-008
Platform Family: 国内自建招聘官网（careers.ctrip.com 携程集团）
页面类型: 内推 / 职位分享流程里的「被推荐人」信息录入
问题字段: `候选人姓名` / `候选人手机号` / `候选人邮箱`
Severity: **P1**（红线类：别人的信息不得用应聘者自己的资料代填）
Stage: MATCH（他人守卫词表缺这一形态）
Status: **bundle_verified**（文案取自站点自己的前端产物；表单本身需登录，未做写入）

## 素材来源（不编造标签）

```bash
curl -sL https://careers.ctrip.com/ > page.html
grep -oE '"[^"]{0,16}候选人[^"]{0,24}"' page.html | sort -u
```

真实文案（携程官网 bundle 内联）：

```
"候选人姓名"
"候选人手机号（请勿填写你的个人信息）"
"候选人邮箱（请勿填写你的个人信息）"
"候选人信息" / "候选人列表" / "分享职位邀请候选人" / "分享职位/我的内推码"
```

括号里那句是站点自己在说：**这一栏写的不是你**。这是内推人替被推荐人填信息的表单。
如果按裸别名走，`姓名 → basic.name`、`手机号 → basic.phone`、`邮箱 → basic.email`
会把应聘者自己的身份写进别人的档案 —— 与姚记真机暴露的「推荐人姓名」同一类错填。

## 修复与取舍

`src/matching/matcher.ts` 的 `OTHER_PERSON_MARKERS` 增加**明示型**短语：
`请勿填写你的个人信息` / `请勿填写您的个人信息` —— 标签里出现即判 `unknown`。

**没有把裸词「候选人」加进词表**：国内 ATS（北森 / 大易 的应聘者中心）也管**应聘者本人**的资料区叫
「候选人信息」，一刀切会把本人字段整体打成需人工，那是大面积少填。
所以只认站点自己明说的形态，并且用一条反向用例把「不过度拦截」钉住。

## 验证

新增 `tests/realLabels.ctrip.test.ts`（3 用例，全部用上面 grep 到的真实字符串）：

1. 三个 `候选人…（请勿填写你的个人信息）` → `unknown`；
2. 反向：`姓名` / `手机号码` 处在 `sectionTitle=候选人信息` 的板块里 → 仍分别命中
   `basic.name` / `basic.phone`（本人资料区不受影响）；
3. `我的内推码`、`推荐人姓名` → `unknown`。

全量单测 **37 文件 / 639 例** 绿；`tsc --noEmit` 零输出；E2E 与三个真机平台 Real Write 在同一次构建上复跑（见 `pilot-log.md` 2026-09-30 行）。
