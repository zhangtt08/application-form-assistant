### Tcode｜个人 Agent 与本机工具编排平台

2026.08 - 2026.10｜独立产品设计与开发

1. 个人项目与能力分散，需要用自然语言统一检索资料、发现工具并执行任务；Tcode 与 WorkflowHub 分别承担任务入口和工具目录。

1. 产品定位与统一入口：围绕个人项目分散、调用方式不一致和重复操作问题，独立构建 Tcode，将已登记的个人项目与工具接入自然语言工作台，统一资料检索、任务理解、工具发现、执行及结果回读。
2. 工具契约与按需调用：通过 REST、MCP 与项目接口对接本机能力，结合 WorkflowHub 进行工具搜索、参数查看和调用；按需加载契约，减少工具 schema 对上下文的占用。当前目录登记 14 个项目、24 个工具。
3. Agent 执行机制：实现多轮 Agent Loop、同轮工具并行、重复调用缓存、步骤清单及结果回填；支持按任务调用已接入项目能力，将对话请求转化为实际文件和操作结果。
4. 知识检索与事实维护：将个人资料、项目 README 和交接文档建立 BM25 索引，回答附带文件与行号；资料修改采用预览、确认和提交机制，保留知识来源与修改控制。
5. 工作流编排：将单工具调用与 DAG 工作流接入统一校验和执行记录，支持 dry-run、节点输入输出、执行日志及产物回看，连接项目工具与日常重复任务。
6. 上下文与会话管理：实现持久会话、长期记忆、历史折叠、摘要与工具结果长度控制；支持模型提供方切换及备用模型降级，管理多轮任务的上下文预算。
7. 执行可观测性与调用约束：以 SSE 展示任务进度，保留工具调用、耗时及 Token 记录；通过工具白名单、风险分级、超时和破坏性命令拦截控制本机操作。
8. 独立开发与桌面交付：以 Node.js 本机服务和 WinForms / WebView2 桌面壳承载交互、检索与执行，结合实际使用反馈持续迭代，将个人工具体系整合为日常可使用的 Agent 产品。
9. 项目成果：形成自然语言任务、知识检索、工具编排、执行反馈与长期记忆的一体化个人工作台，能够调用当前已接入的个人项目能力。

### AgentCut｜人机共用剪辑软件

2026.10 - 2026.10｜独立开发

1. 针对剪辑流程缺少稳定 Agent 工具入口及共享工程状态的问题，构建人机共用时间线的本地剪辑软件。

1. 需求识别与产品构建：针对传统剪辑软件缺少稳定 Agent 操作入口的问题，独立构建人和 Agent 共用同一时间线的桌面剪辑软件，以 Electron / React 交互层配合 Python、FFmpeg 引擎，并开放 HTTP / MCP 调用。
2. 编辑契约与状态一致性：统一界面操作和 Agent 批命令语义，通过原子事务、request_id 幂等回执、expected_revision 校验及 dry-run，控制重复提交与并发覆盖，支持可追踪的自动化编辑。
3. 媒体编辑能力：完成素材探测、时间线拖拽与修剪、分割、关键帧、曲线变速、字幕导入、转场、遮罩及嵌套合成，建立统一的素材与工程管理方式。
4. 画面处理与导出验证：支持每通道曲线、白平衡、RGB 增益及串行调色节点，以同源参数驱动预览和 FFmpeg 导出，并通过实际像素、视频时长及音画同步检查处理结果。
5. 音频及批量制作：实现 EBU R128 响度检测与统一、静音检测去空白、配乐自动闪避、代理回放和缓存配额，支持口播与多素材制作中的重复处理。
6. 任务交付与恢复：将固定工程版本绑定持久渲染队列，支持取消、多画幅批量交付、历史快照恢复及工程素材打包，完成可运行桌面程序。
7. 项目成果：交付具有真实媒体处理与导出能力的桌面剪辑产品，界面、HTTP 和 MCP 共用编辑规则，支持人工编辑与 Agent 工具调用。

### ACB｜跨机器项目与 Agent 上下文交接系统

2026 - 2026｜独立开发

1. 针对跨电脑、跨 Agent 继续开发时的代码状态和上下文遗漏，构建项目捕获、交接、校验与恢复工具。

1. 交接问题抽象：针对跨电脑、跨 Agent 接续开发时代码状态与上下文分离的问题，独立构建 ACB，将 Git 历史基线、工作区变更和项目决策一起封装为可校验的交接包。
2. 代码状态捕获：基于 Git Bundle 保留历史，分别记录暂存和未暂存修改；发布交接保持源项目分支、HEAD 和工作区状态不变，使在途开发能够完整交接。
3. 结构化上下文：整理目标、约束、已作决策、阻塞、下一步和环境缺口，生成 Agent 可直接阅读的接手文件，为后续执行提供明确入口。
4. 校验与恢复：先检查包完整性再恢复至新目录，对非空目标目录进行拦截；区分历史验证证据、目标电脑待验证项和执行器错误，形成接手状态报告。
5. 独立实现与交付：使用 Express、React 和 TypeScript 完成捕获、封包、传输、校验及恢复流程，连接代码快照、上下文和后续任务执行。
6. 项目成果：形成可实际使用的项目接力工具，减少跨环境交接中的代码状态遗漏与决策丢失，并明确环境配置、重新验证和恢复受阻等处理事项。

### Application Form Assistant｜网申资料库与自动填写助手

2026 - 2026｜独立产品设计与开发

1. 针对网申字段结构不同、岗位表达切换和重复填写，构建本地资料库与语义识别自动填写插件。

1. 需求分析与插件构建：针对招聘网站字段结构不同、重复填写及岗位表达切换的问题，独立开发 Manifest V3 Edge 插件，以 TypeScript、React 和 Vite 实现侧边栏、页面内容脚本及本地资料管理。
2. 资料模型与岗位适配：设计共享基本信息和分岗位资料库，统一管理教育、联系信息及岗位定制的实习、项目、技能与自我介绍；将背景、职责、工作内容和成果拆分为可复用语义槽位。
3. 表单语义识别：结合网页标签、上下文、字段别名、经历区块与置信度识别求职字段，通过岗位方向选择对应资料内容，过滤登录、密码、搜索框及不确定敏感字段。
4. 复杂页面适配：处理 React 受控输入、下拉选项、重复经历区块、iframe 与 Shadow DOM 的写入及验证，保留不确定项的人工处理与失败反馈。
5. 数据导入与结果确认：支持 JSON 导入、结构校验及本地保存，结合网页字段长度约束处理内容；自动填写与最终提交分离，使用户能够检查后再提交。
6. 测试与产品迭代：围绕字段匹配、框架输入、兼容性和隐私建立回归测试，保留结果确认、本地日志和异常反馈，持续优化实际使用中的识别与填写流程。
7. 项目成果：形成可在 Edge 使用的岗位资料库与自动填写产品，支持同一背景按岗位组织内容、本地保存及结构校验。
